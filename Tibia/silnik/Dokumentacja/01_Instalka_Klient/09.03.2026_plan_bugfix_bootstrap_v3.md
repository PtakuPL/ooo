# Plan naprawy bootstrap launchera v3 — 09.03.2026

## Zgłoszone problemy

1. **Brak pytania o język** — bootstrap nie pokazał dialogu wyboru języka
2. **Anuluj w folderze nie przerywa** — po wyborze "Nie" (chcę wybrać folder) → anulowanie folderu instaluje w domyślnej lokalizacji zamiast przerwać
3. **Angielski tekst po wyborze polskiego** — "Click YES to install here..." zamiast po polsku (wymaga rekompilacji — kod już naprawiony)
4. **Nie mogę się zalogować na launcher** — konto działa na stronie, ale launcher odrzuca login

---

## Analiza przyczyn

### P1 — Brak dialogu języka
- `resolve_language()` sprawdza `language.conf` — jeśli istnieje, pomija dialog
- Plik: `%LOCALAPPDATA%\RedDaxe\language.conf`
- **Przyczyna**: user uruchomił wcześniej bootstrap, który zapisał `language.conf`. Następne uruchomienie pomija dialog.
- **Zachowanie jest poprawne** — dialog pokazuje się tylko za pierwszym razem. Ale powinien być sposób na reset języka.
- **Fix**: Dodać flagę `--choose-language` do bootstrapa, która wymusza dialog (np. dla helpdesku). ALBO: usunąć `language.conf` ręcznie wymusza reset.
Więc powinienem móc także za pomoca odinstaluj wszystko usunąć plik language.conf aby to nie psuło właśnie działania juz pobranego launchera. 

### P2 — Anulowanie folderu nie przerywa instalacji
- Plik: `platform.rs` linia ~103
- Kod: `win_browse_for_folder(title).or_else(|| Some(default.to_path_buf()))`
- **Przyczyna**: Gdy user anuluje folder picker, `win_browse_for_folder` zwraca `None`, a `.or_else()` podmienia to na domyślną ścieżkę.
- **Fix**: Zmienić `ask_install_dir()` żeby zwracało `Option<PathBuf>` — `None` = user anulował. W `main.rs` obsłużyć `None` jako przerwanie instalacji.

### P3 — Angielski tekst w dialodze (wymaga rekompilacji)
- **Status**: Naprawione w kodzie (poprzednia sesja) — dodano `install_dir_hint` do i18n z 5 tłumaczeniami
- **Wymaga**: push + build na GHA + deploy nowego ZIPa

### P4 — Nie można zalogować się na launcher
- Endpoint `login.php` wymaga `launchToken` gdy `CLIENT_LOCKED=true`
- Fresh install (brak `installed_state.json`) pomija token — login bez tokena
- `CLIENT_LOCKED=true` w `.env` → login.php odrzuca żądania bez tokena z błędem `LCH_TOKEN_REQUIRED`
- **Przyczyna**: Bootstrap instaluje launcher, launcher nie ma `installed_state.json`, ustawia `fresh_install=true`, pomija token → login.php widzi brak tokena → odrzuca z `LCH_TOKEN_REQUIRED`
- **Fix**: Dwie opcje:
  - **Opcja A** (szybka): Zmienić `CLIENT_LOCKED=false` w `.env` na czas developmentu
  - **Opcja B** (prawidłowa): W `login.php` dodać wyjątek: jeśli brak `installed_state.json` (fresh install), nie wymagaj tokena. Launcher wysyła flagę `freshInstall: true` w requeście → login.php akceptuje brak tokena dla fresh installa.

  
  Opcja B
